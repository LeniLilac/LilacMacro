# Privacy

**Status: Implemented behavior. Notice version 1, effective August 15, 2026; updated August 16, 2026.**

LilacMacro is a local Windows tool. Before its first Macro session, it presents three independently saved choices: online features and product telemetry are initially shown on, while automatic error reports are initially off. The user must durably save that screen before any request covered by those choices can occur, and all three choices remain editable in Settings. Later telemetry and automatic-report opt-outs revoke their consent generation immediately; turning online features off prevents new service and update-check requests, although one already in flight can finish and update its local public cache. Opt-ins activate only after the atomic settings write succeeds. Failed writes are retried and shown as unsaved while affected paths remain off. Other network access is limited to explicit OCR setup/model downloads, owner-approved update downloads, a runner's first-use Roblox login/installer bootstrap, and a separately enabled manual diagnostic upload.

## Data handling rules

- Keep datasets, screenshots, OCR crops, agent views, logs, settings, and models out of Git.
- Inspect only datasets the owner explicitly places in scope.
- Do not upload captures or logs except through the explicit LilacMacro Services diagnostic flow described below.
- Treat deep-debug ZIPs as private captures even though known text secrets and profile paths are redacted; game pixels can still contain personal data.
- Redact local usernames, private-server links, webhook URLs, and other secrets from issues, test fixtures, diagnostics, and documentation.
- Delete local datasets and caches through ordinary Windows file management when no longer needed; LilacMacro does not currently provide a data-erasure workflow.
- Optional runner setup is runner-profile-only. It must not remove packages, startup entries, notifications, or settings from the owner's profile or all users.
- Treat the provisioning journal as sensitive system metadata even though it contains no credential. Access is restricted to the owner, SYSTEM, and Administrators.
- Roblox settings normalization is restricted to the current Windows profile and preserves unknown fields, identifiers, graphics quality, FPS, audio, window placement, and unrelated preferences. It never reads or writes Roblox process memory.

## Online features and product telemetry

When online features are enabled, LilacMacro polls the signed public control snapshot, obtains public game codes and maintenance/feature-disable state, checks official GitHub release metadata when configured, and permits explicit configuration sharing. Export sends one compressed opaque bundle containing only the selected Plan and/or saved placement documents to LilacMacro Services over trusted HTTPS. It excludes private-server links, Discord settings, privacy choices, run history, diagnostics, and other application settings. The service returns a random 20-character bearer code, stores only its SHA-256 hash, stores a separate payload-integrity hash, and uses a monthly rotating share-specific network pseudonym only for daily abuse limits. Retrieval access automatically ends 30 days after creation; expired records enter bounded background deletion, and a service outage or retry can delay physical removal. Anyone with the code can retrieve the bundle before expiry, so users should share codes privately. Retrieval puts the code in a no-store JSON request body rather than a logged URL. Import always requires an explicit code and component selection, is rejected while another Macro uses that configuration, and rolls back staged placement replacements if the combined import fails. Imported Plans are added without replacing an existing Plan, while selected placement documents replace matching local map files. Turning the online-features choice off prevents new LilacMacro service and update-check requests; one bounded request already in flight can finish and update its local public cache. Local automation remains available without current remote safety status.

When product telemetry is enabled, LilacMacro sends only a fixed bounded schema: application version; feature and outcome identifiers; expedition reward material and quantity observations; error counters without free-form exception text; OCR inference duration and CPU/GPU execution category; Windows version; logical processor count; and process capability. Batches contain at most 64 events and 64 KiB. The client holds at most 256 unsent events in memory, drops older events under pressure, has no disk retry queue, and never interrupts automation when delivery fails. An opt-out cancels this process's queued and cooperative in-flight work; a request from another shared process that already reached the service can finish, but that process rechecks the authoritative consent generation before any later send.

Telemetry never includes screenshots, OCR text, file paths, Roblox credentials, private-server links, Discord webhook URLs, raw hardware identifiers, or raw IP addresses. The random installation UUID is transmitted over trusted HTTPS and immediately converted by LilacMacro Services to a monthly rotating, telemetry-specific HMAC pseudonym. The service does not store the raw UUID with events or implement a join to diagnostic data; distinct stored HMAC domains are not directly joinable at rest. A separate telemetry-network HMAC pseudonym owns only a daily abuse quota. Telemetry is used for active-installation estimates, feature use, error-prone states, OCR performance, and manually reviewed expedition reward research. It never automatically changes bundled distributions or remote policy. Server telemetry and quota records become eligible for scheduled deletion after 90 days; bounded retries can delay physical removal during an outage.

## Automatic and manual diagnostic uploads

**Automatic reports:** This choice defaults off and is independent of telemetry and manual uploads. With Deep Debug off, a macro or application error packages a sanitized event timeline, non-secret display/plan counts, coarse environment information, safe OCR/model/profile identifiers, macro actions, and at most 32 already-acquired frames. The archive hard limit is 80 MiB and light reports are rate-limited to one per 15 minutes. OCR text, arbitrary exception text, local paths, private-server links, Discord settings, and credentials are excluded. Captured Roblox pixels can still contain personal game data.

When Deep Debug is active, the completed Deep Debug archive is sent instead. Temporary light archives are deleted after the upload attempt. A successfully sent Deep Debug archive is deleted; if Windows temporarily locks it, LilacMacro records an empty exact-name deletion marker and retries at orderly close and the next startup. A failed Deep Debug upload remains local for inspection or retry. Turning automatic reports off clears this process's in-memory light buffer, cancels cooperative work, and prevents automatic discovery/upload. The independent local-cleanup choice may still prune completed archives to the newest 20; disabling cleanup does not enable a report or upload. A request from another shared process that already reached the service can finish, but that process rechecks the authoritative consent generation before any later upload.

**Manual uploads:** The existing manual diagnostic upload choice defaults off. Enabling it only exposes an `UPLOAD ARCHIVE` action, and every manual transfer requires the user to choose one local ZIP through the file picker. Disabling it blocks new manual uploads, and Cancel interrupts hashing or transfer work. This choice does not enable automatic reports.

The client hashes the complete archive before requesting a grant, binds the exact filename, size, SHA-256, kind, application version, random installation UUID, and explicit-consent flag, rejects redirects, and accepts storage grants only for the official Backblaze B2 S3 origin and diagnostic object prefix. Single and multipart transfers bind exact byte lengths and SHA-256 checksums. Authorization tokens and signed storage URLs are session-only and are never logged or persisted.

Retrieval access for routine archives through 3 GiB expires 72 hours after server verification. Archives over 3 GiB through the absolute 30 GiB limit require a short-lived administrator grant, must be accepted within 30 minutes, and otherwise enter deletion; accepted access expiry defaults to 72 hours and may be extended to no later than seven days. Expired objects enter the deletion queue, and bounded retries can delay physical removal during an outage. LilacMacro Services applies upload quotas using the random installation UUID and a server-secret network pseudonym rather than storing a raw IP address. Roblox pixels can still contain account, chat, inventory, or other personal game data, so users should inspect the selected archive before uploading it.

Settings shows the random Installation ID so a user can request a large-file grant. The user sends
that ID, the archive's exact byte size, and archive kind to an administrator, then pastes the returned
30-minute grant into the Large File Grant field before selecting the ZIP. The ID is random and is not
a hardware identifier. The grant is short-lived, bound to that exact request, and should not be
shared publicly.

## Secret storage

**Prototype:** Settings displays the Roblox private-server link as editable account-routing configuration and masks the Discord webhook. Both values store only DPAPI ciphertext. Private-server navigation parses the value in memory, launches a reduced `roblox://` target through the registered protocol, and never writes the plaintext link to command output, settings JSON, or diagnostics. Discord delivery accepts only the official stable, PTB, or Canary HTTPS execute-webhook shape, rejects redirects, uses a bounded background queue, and formats compact Components V2 messages for the independently selected run, task, result, recovery, and terminal-failure events. Mentions are disabled by default; only a validated configured Discord user ID may be explicitly allowlisted for a terminal-failure notification. Webhook URLs and response bodies never appear in surfaced delivery failures. If DPAPI decryption fails, the unusable value is discarded in memory rather than exposed or treated as configured; explicit recovery UX remains Planned.

## External software

OCR setup installs pinned PaddlePaddle and PaddleOCR packages into the local LilacMacro environment. Those packages and their model downloads are governed by their own licenses and services. See [NOTICE.md](NOTICE.md) and the files under [`licenses`](licenses/) for bundled attributions.

The prototype installer also bundles pinned TermWrap v0.6 binaries and notices. It never downloads or replaces native session components at runtime. Managed instances use only loopback RDP and disable clipboard, drive, printer, smart-card, microphone, and device redirection. See [Local instance manager](docs/LOCAL-SESSION.md).

On a managed runner's first full-UI launch, LilacMacro opens the official Roblox Login page. If Roblox is absent, it follows only the official `roblox.com` download endpoint to a bounded `rbxcdn.com` installer URL, requires a trusted Authenticode signature, and starts the visible installer. LilacMacro never enters, stores, or transfers Roblox credentials.
