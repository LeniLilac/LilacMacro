# Privacy

**Status: Implemented behavior. Notice version 4, effective August 21, 2026.**

LilacMacro is a local Windows tool. Before its first Macro session, it presents three independently saved choices: online services, limited usage data, and Deep Debug error uploads are initially shown on. The user must durably save that screen before any request covered by those choices can occur, and all three choices remain editable in Settings. Later telemetry and error-upload opt-outs revoke their consent generation immediately; turning online services off prevents new service and update-check requests, although one already in flight can finish and update its local public cache. Opt-ins activate only after the atomic settings write succeeds. Failed writes are shown as unsaved while affected request paths fail closed. After the first-run choices are saved, a supported NVIDIA GPU may trigger the separately identified GPU OCR setup screen; that setup downloads only the matching OCR package for the current Windows user. Other network access is limited to later explicit OCR setup/model downloads, owner-approved update downloads, and a runner's first-use Roblox login/installer bootstrap.

## Current local data

Local roots use current-user DPAPI; ACL-restricted ProgramData roots use machine-scope DPAPI. Only the recorded provisioning owner and selected managed runners adopt a shared root; another Windows profile on the machine remains local. | Deep-debug archives | `%ProgramData%\LilacMacro\Diagnostics` after local-instance provisioning; otherwise `%LOCALAPPDATA%\LilacMacro\diagnostics` | Sanitized text plus Roblox/crop/ROI pixels. Capture is fixed at one second. Older ordinary frames may be stored as decode-verified quality-14 JPEG; important frames use pixel-exact AVIF only when smaller and otherwise remain PNG. Compression happens locally and does not change which pixels may be included. At the 3 GiB limit, only enough low-priority evidence is removed to fit; classified failures protect nearby frames. The protected ProgramData directory is shared by the provisioning owner and all configured runners. `MAX LOG STORAGE, GB` is one machine-wide byte budget with a free-space-derived default of 3, 10, or 30 GiB; capture temporarily pauses below 3 GiB free. Existing profile-local archives are not moved or deleted during provisioning. |
| Diagnostic upload identity | Active configuration root under `services\diagnostic-installation.json` | Random installation UUID used for upload quotas. No covered request occurs until the current notice is saved. |

| Optional local-runner journal | `%ProgramData%\LilacMacro\Session` | Prototype, machine-owned resource inventory, original system values, hashes, policy version, and owner/runner SIDs. Contains no password. |
| Local instance profiles and configuration | `%ProgramData%\LilacMacro\Profiles` and `Configurations` | Profile policy/receipt per runner plus shared or isolated macro configuration. Shared configuration survives instance removal; isolated configuration is removed with its runner. Roblox login data is never copied. |
| Optional runner credential | Windows Credential Manager | Prototype, random runner-account credential persisted for the loopback RDP endpoint. Never stored in JSON or passed on a command line. |

## Data handling rules

- Keep datasets, screenshots, OCR crops, agent views, logs, settings, and models out of Git.
- Inspect only datasets the owner explicitly places in scope.
- Do not upload captures or logs except through the explicit LilacMacro Services diagnostic flow described below.
- Treat deep-debug ZIPs as private captures even though known text secrets and profile paths are redacted; game pixels can still contain personal data.
- The provisioning owner and every configured runner account can access the shared machine diagnostics directory. Do not provision a runner account for someone who must not be able to inspect those captures.
- Redact local usernames, private-server links, webhook URLs, and other secrets from issues, test fixtures, diagnostics, and documentation.
- Delete local datasets and caches through ordinary Windows file management when no longer needed; LilacMacro does not currently provide a data-erasure workflow.
- Optional runner setup is runner-profile-only. It must not remove packages, startup entries, notifications, or settings from the owner's profile or all users.
- Treat the provisioning journal as sensitive system metadata even though it contains no credential. Access is restricted to the owner, SYSTEM, and Administrators.
- Roblox settings normalization is restricted to the current Windows profile and preserves unknown fields, identifiers, graphics quality, FPS, audio, window placement, and unrelated preferences. It never reads or writes Roblox process memory.

## Online features and product telemetry

When online features are enabled, LilacMacro polls the signed public control snapshot, obtains public game codes and maintenance/feature-disable state, checks official GitHub release metadata when configured, and permits explicit configuration sharing. Export sends one compressed opaque bundle containing only the selected Plan and/or saved placement documents to LilacMacro Services over trusted HTTPS. It excludes private-server links, Discord settings, privacy choices, run history, diagnostics, and other application settings. The service returns a random 20-character bearer code, stores only its SHA-256 hash, stores a separate payload-integrity hash, and uses a monthly rotating share-specific network pseudonym only for daily abuse limits. Retrieval access automatically ends 30 days after creation; expired records enter bounded background deletion, and a service outage or retry can delay physical removal. Anyone with the code can retrieve the bundle before expiry, so users should share codes privately. Retrieval puts the code in a no-store JSON request body rather than a logged URL. Import always requires an explicit code and component selection, is rejected while another Macro uses that configuration, and rolls back staged placement replacements if the combined import fails. Imported Plans are added without replacing an existing Plan, while selected placement documents replace matching local map files. Turning the online-features choice off prevents new LilacMacro service and update-check requests; one bounded request already in flight can finish and update its local public cache. Local automation remains available without current remote safety status.

When product telemetry is enabled, LilacMacro sends only a fixed bounded schema: application version; feature and outcome identifiers; expedition reward material and quantity observations; error counters without free-form exception text; OCR inference duration, CPU/GPU execution category, and a normalized public CPU or GPU model name; OCR setup failure code, stage, requested device, bounded setup duration and process exit code, and four boolean runtime-presence flags; local-instance operation failure code, operation, configuration mode, bounded duration, runner count, and process exit code; primary-display pixel dimensions; UI Scale input and observed rendered-scale values; Windows version; and logical processor count. Model names are accepted only for known CPU/GPU vendors, stripped of trademark punctuation and unsupported characters, and limited to 96 characters. Batches contain at most 64 events and 64 KiB. The client holds at most 256 unsent events in memory, drops older events under pressure, has no disk retry queue, and never interrupts automation when delivery fails. A small local ledger records successfully sent failure-code/scope/version combinations so repeated failures are not repeatedly reported; it is not an event queue and contains no exception text. An opt-out cancels this process's queued and cooperative in-flight work; a request from another shared process that already reached the service can finish, but that process rechecks the authoritative consent generation before any later send.

Telemetry never includes screenshots, OCR text, file paths, Roblox credentials, private-server links, Discord webhook URLs, hardware serial numbers or device IDs, or raw IP addresses. The random installation UUID is transmitted over trusted HTTPS and immediately converted by LilacMacro Services to a monthly rotating, telemetry-specific HMAC pseudonym. The service does not store the raw UUID with events or implement a join to diagnostic data; distinct stored HMAC domains are not directly joinable at rest. A separate telemetry-network HMAC pseudonym owns only a daily abuse quota. Telemetry is used for active-installation estimates, feature use, error-prone states, OCR performance by hardware model, UI-scale calibration across display resolutions, and manually reviewed expedition reward research. It never automatically changes bundled distributions or remote policy. Server telemetry and quota records become eligible for scheduled deletion after 90 days; bounded retries can delay physical removal during an outage.

## Automatic diagnostic uploads

This choice defaults on for a newly presented notice and is independent of usage data. It sends only a completed Deep Debug archive containing a classified terminal or recoverable failure. There is no smaller light-report fallback: disabling Deep Debug or entering its below-3-GiB low-disk pause also pauses automatic error uploads. A no-error Deep Debug archive remains local and is not uploaded automatically.

Deep Debug archives contain sanitized ordered events, macro actions, bounded environment/configuration data, safe OCR/model/profile identifiers, bounded OCR observations, and one-second PNG, JPEG, or AVIF evidence. During capture, the newest ten seconds remain PNG while they can still become pre-error evidence. Older ordinary frames use the Windows imaging component to create decode-verified quality-14 JPEG; at finalization, important frames use AVIF only after a pixel-exact validation and only when smaller, otherwise PNG is preserved. Each frame's format, quality, sizes, and validation result are recorded. If compression cannot keep the archive within 3 GiB, only enough evidence is removed to fit. Old lossy ordinary frames are removed before important transitions and classified-error windows; error windows merge, and retention favors terminal, first-signature, visually distinct, and recent evidence before repeated near-identical errors. Every completed archive is checked against the 3 GiB hard limit. Text redaction removes known private-server links, webhook URLs, Windows usernames, and profile paths, but OCR observations and captured Roblox pixels can still contain personal game data.

Successfully sent and failed Deep Debug archives both remain local for inspection. Turning error uploads off cancels cooperative work and prevents later automatic upload. Local retention remains active independently and deletes the oldest archives only when needed to remain within the configured shared byte budget, always preserving the newest completed archive. A request from another shared process that already reached the service can finish, but that process rechecks the authoritative consent generation before any later upload.

The client hashes the complete automatic archive before requesting an upload, binds the exact filename, size, SHA-256, kind, application version, random installation UUID, and explicit-consent flag, rejects redirects, and accepts storage grants only for the official Backblaze B2 S3 origin and diagnostic object prefix. Single and multipart transfers bind exact byte lengths and SHA-256 checksums. The single archive limit is 3 GiB. Authorization tokens and signed storage URLs are session-only and are never logged or persisted.

Retrieval access expires 72 hours after server verification. Expired objects enter the deletion queue, and bounded retries can delay physical removal during an outage. LilacMacro Services applies upload quotas using the random installation UUID and a server-secret network pseudonym rather than storing a raw IP address. Roblox pixels can still contain account, chat, inventory, or other personal game data.

## Secret storage

**Prototype:** Settings displays the Roblox private-server link as editable account-routing configuration and masks the Discord webhook. Both values store only DPAPI ciphertext. Private-server navigation parses the value in memory, launches a reduced `roblox://` target through the registered protocol, and never writes the plaintext link to command output, settings JSON, or diagnostics. Discord delivery accepts only the official stable, PTB, or Canary HTTPS execute-webhook shape, rejects redirects, uses a bounded background queue, and formats compact Components V2 messages for the independently selected run, task, result, recovery, and terminal-failure events. Real runtime events attach one bounded current Roblox client PNG when capture is available; the Test webhook action remains text-only, and capture or upload failure does not stop automation. These screenshots may contain account names, chat, inventory, or other content visible in Roblox and are not written to disk by the webhook capture path. Mentions are disabled by default; only a validated configured Discord user ID may be explicitly allowlisted for a terminal-failure notification. Webhook URLs and response bodies never appear in surfaced delivery failures. If DPAPI decryption fails, the unusable value is discarded in memory rather than exposed or treated as configured; explicit recovery UX remains Planned.

## External software

Official installers bundle Python 3.12, the pinned CPU PaddlePaddle/PaddleOCR runtime, and the allowlisted OCR models. Optional GPU setup downloads the matching pinned Paddle GPU package into the current user's local OCR environment; it does not install a Python distribution or NVIDIA driver. Those packages, models, and their download services are governed by their own licenses and terms. See [NOTICE.md](NOTICE.md) and the files under [`licenses`](licenses/) for bundled attributions.

The prototype installer also bundles pinned TermWrap v0.6 binaries and notices. It never downloads or replaces native session components at runtime. Managed instances use only loopback RDP and disable clipboard, drive, printer, smart-card, microphone, and device redirection. See [Local instance manager](docs/LOCAL-SESSION.md).

On a managed runner's first full-UI launch, LilacMacro opens the official Roblox Login page. If Roblox is absent, it follows only the official `roblox.com` download endpoint to a bounded `rbxcdn.com` installer URL, requires a trusted Authenticode signature, and starts the visible installer. LilacMacro never enters, stores, or transfers Roblox credentials.
