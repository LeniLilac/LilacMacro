# Project status

**Status: Current as of 2026-08-23.** Update this matrix in the same change that moves a capability across a boundary.

The [documentation contract](../CONTRIBUTING.md#documentation-contract) defines the status terms. In short: **Implemented** means production capability exists, **Prototype** means usable but internal or incomplete code exists, **Planned** means accepted design intent, and **Unresolved** means a decision remains open.

## Accepted target architecture

The Prototype priority scheduler now pauses on the Windows offline signal before starting a plan attempt or retrying recovery, then resumes the existing bounded restart/rejoin ladder after connectivity returns. This gate does not add an online request and does not classify a Roblox-only service outage as local internet loss. A fresh or invalidated plan configuration starts with exactly one empty plan named `Plan 1`; persisted user plans are preserved.

## Important non-equivalences

- A Debug click proves a bounded transition can be inspected; it does not implement a mode runner.
- A saved placement timeline proves authoring and validation; only an explicit Setup test, Runtime Lab run, or supported macro runner authorizes playback.
- OCR confidence is recorded evidence; it does not independently authorize unattended input.
- Direct `Repeat Stage` remains Debug evidence when invoked manually; the scheduler also owns it for an exact same-task Story/Raid/Expedition/Event continuation after priority is reevaluated.
- Dataset Builder and Runtime Lab are retained owner tools, not legacy code marked for removal.
