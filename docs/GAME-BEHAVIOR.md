# Game behavior ledger

**Status: Prototype field evidence.** This document describes current, owner-triggered OCR Debug behavior. It does not describe an unattended macro loop.

## Global Debug contract

- Roblox must be a freshly verified `1366 x 700` client area.
- The monitor containing Roblox must use 100% Windows display scale. Every input episode rechecks its effective DPI and stops with the detected percentage before input when it differs.
- Every state loads the first annotation from the configured finalized dataset frame as its OCR region of interest (ROI), unless the state names an owner-labeled annotation explicitly.
- Runtime Lab Debug defaults to OCR. Its `IMAGE + OCR FALLBACK` option first evaluates the state's selected `IMAGE` elements from saved per-user profiles; incomplete image evidence runs `PP-OCRv6_small_rec` with its paired detector inside the dataset ROI.
- Normal matching keeps only ASCII `A-Z`, `a-z`, and `0-9`, lowercases letters, removes spacing and symbols, and accepts the normalized alias as a substring.
- Exact states require normalized equality. Repeated states require separate OCR rectangles.
- A state must pass before its action. Actions still require fresh OCR-owned target bounds or freshly verified relational anchors even when a preceding check passed through image evidence.
- Roblox is revalidated immediately before input. Its current monitor is required to remain at 100% Windows display scale, and the complete client is moved inside that monitor's usable work area and verified before client-relative coordinates are converted, preventing taskbars or off-screen edges from receiving the action. Missing or ambiguous evidence blocks input; there are no static-coordinate fallbacks.

Dataset paths below are relative to `Documents\LilacMacro Datasets`.

## Startup settings normalization

- At Main Macro plan start and every private-server Lobby reset, the owning Windows session terminates its Roblox client process tree, waits for process exit, normalizes the current profile's `GlobalBasicSettings_13.xml`, converts the validated private-server share/link code to a registered `roblox://` target, and launches Roblox directly without opening a browser. The lifecycle uses at most two process-tree termination passes and rediscovers current-session clients before each pass, covering Roblox's observed PID handoff without waiting on its close-confirmation surface. Clients in other Windows sessions are not targeted.
- The XML edit requires exactly one structurally valid `UserGameSettings` item. It atomically normalizes only text size, chat/stats/player-list visibility, fullscreen, classic camera, keyboard/mouse movement, Shift Lock control mode, inverted camera, scalar plus first/third-person mouse sensitivity, UI-navigation key capture, VR, profiler overlays, preferred transparency, and reduced motion. Unknown fields, graphics quality, FPS cap, volume, window placement, identifiers, and unrelated settings are preserved. A transient sibling backup supports interrupted replacement recovery and is removed after a successful reread.
- If Roblox has not created `GlobalBasicSettings_13.xml`, startup stops with the launch-and-close prerequisite. Unattended recovery must not restart Roblox for a missing file that only the prerequisite can create.
- Each full Macro run normalizes rendered UI scale once after its initial private-server join. It closes Settings, reopens it, applies the fixed in-game option profile below, closes Settings again, and then begins task navigation. Recovery and terminal private-server joins still normalize the Roblox XML before launch and freshly verify Lobby, but do not repeat either in-game pass. Runtime Lab Debug exposes both the isolated UI-scale action and the complete startup sequence for owner testing; neither is a user-disableable Macro option.
- Normalization first requires two consecutive fresh Lobby observations. Two stable panel observations retain an already-open Settings surface; otherwise the Settings button is verified through its dark control and centered multi-quadrant gear structure before it is clicked. Four bounded verified attempts are distributed across the complete observation window rather than exhausted during its first seconds, and each observation records panel/gear evidence in Deep Debug. ## Observed transitions

- An action that owns `source -> destination` always verifies the expected destination first. Only when destination evidence fails does it inspect the source. Destination present means success, source retained means the action may be safely reacquired and retried, and neither state means an indeterminate transition that expands its bounded observation interval without input. Destination evidence wins when an overlay leaves both states visible, and the successful fast path never pays for redundant source OCR.
- Source and destination/modal layers use distinct dataset-labeled ROIs even when both render the same word. A broad union crop and topmost/bottommost duplicate-label heuristic are invalid click ownership. Expedition checkpoint Continue and Extract therefore observe their source controls separately from their confirmation panels; confirmation clicks come only from the panel ROI. If that panel disappears but the checkpoint source returns in two consecutive fresh observations, the transition reopens and retries instead of reporting success.
- Each transition episode caps action attempts and indeterminate observations independently, remains cancellable, and records both counts in deep debug. Consuming the final allowed action does not end the episode before the expected clear or destination can be observed; the observation budget remains available without authorizing another click.
